## 开始工作前
1. 阅读相关的 Issue、PRD、OpenSpec 变更和 `.trellis/spec` 中的规范。
2. 先搜索已有实现，优先复用。
3. 先说明计划，等人确认后再大范围修改。
4. 需求不清楚或有多种合理方案时，先提问。

## 必须遵守
- 只修改当前任务相关的文件。
- 新增或改变行为时补充测试。
- 数据库结构变更必须通过迁移。
- 不提交密钥、真实客户数据或生产配置。
- 不引入新依赖，除非说明理由并得到确认。
- 不删除、跳过或放宽测试来通过检查。

## 公司 Skill
Skill 位于 `.agents/skills/`。工具不能自动发现时，在对应场景直接阅读这些文件：
- 处理缺陷、测试或构建失败：`team-systematic-debugging`
- 准备说“完成了”、提交或创建 PR 之前：`team-verification-before-completion`
- 收到审查意见或修改要求：`team-receiving-code-review`

## 必须由人确认
- 登录、权限、支付和计费
- 数据库迁移和删除数据
- CI、部署脚本和生产配置
- 向外部服务发送用户数据
- git push、创建 PR、rebase

## 禁止
- 推送或强推 main、release/*
- git reset --hard、git clean -fd
- 合并或批准 PR，打发布标签
- 操作生产数据库和生产服务器

## 完成标准
- `make check` 通过，并贴出真实结果。
- 说明改了什么、怎么验证、还有什么风险。
- 没有运行的检查要明确说明，不能声称已通过。
