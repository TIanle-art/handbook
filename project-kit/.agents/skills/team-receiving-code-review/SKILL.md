# 处理审查意见

审查意见要认真对待，但不盲目照改。先理解，再判断，再修改。

## 步骤

1. **逐条理解**
   - 区分意见的级别：`blocking`（必须改）、`suggestion`（建议）、`question`（提问）、`nit`（小问题）。
   - 不确定审查人的意思时，先提问，不要猜。

2. **核实意见是否正确**
   - 对照代码、需求和规范，确认问题是否真实存在。
   - 能写测试复现的，先写测试。
   - 如果意见基于错误的理解，或者会破坏已有行为，说明理由和证据，不要直接照改。

3. **修改**
   - 每条意见对应明确的修改，用新的提交完成，不改写已审查的提交。
   - 只改意见涉及的内容，不顺手做无关的重构。
   - 意见之间有冲突，或修改会影响架构、权限、数据结构时，先向人确认。

4. **验证**
   - 运行 `make check`，确认修改没有破坏其他功能。

5. **回复**
   - 对每条意见回复处理结果：已修改（说明改了哪里）、不修改（说明理由）、需要讨论。
   - 修改较大时，提醒请求重新审查。

## 注意

- 不要为了“让审查通过”而删除测试、关闭检查或放宽规则。
- 不要因为意见来自 AI 就全部接受，也不要因此全部忽略。
- 业务规则上的分歧，交给项目负责人或业务拍板人决定。
