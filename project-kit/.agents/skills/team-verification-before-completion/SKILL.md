# 完成前验证

没有实际运行的证据，就不能说完成。

## 步骤

1. **对照验收标准**
   - 重新读一遍 Issue、PRD 或 OpenSpec 变更中的验收标准。
   - 逐条确认是否满足，列出没有满足或无法确认的条目。

2. **运行检查**
   - 运行 `make check`。
   - 改动涉及某个子项目时，也运行它自己的测试命令。
   - 保留真实的输出，包括失败的部分。

3. **检查改动范围**
   - 运行 `git status` 和 `git diff`，确认：
     - 没有与任务无关的改动。
     - 没有调试代码、临时文件、日志或密钥。
     - 没有删除、跳过或放宽测试。
     - 数据库结构变化都有迁移。
     - 接口变化后，生成的类型已更新。

4. **验证主要流程**
   - 能在本地运行时，实际走一遍主要流程和一个错误场景。
   - 不能运行时，明确说明原因。

## 报告格式

```markdown
## 结果
- 改了什么：
- 验收标准：逐条说明是否满足

## 验证
- `make check`：通过 / 失败（附关键输出）
- 手工验证：做了什么，结果如何
- 没有运行的检查及原因：

## 风险和遗留问题
-
```

## 禁止的说法

在没有对应证据时，不要说：

- “应该可以了”“理论上没问题”
- “测试通过”（没有运行测试）
- “已修复”（没有复现并验证）

检查失败时，如实报告失败，不要只报告通过的部分。
