# 建模板的经验（后续模板都读这个文件）

## 本机环境
- 本机 shell 是 zsh：`TOOLS="--claude --cursor"` 再写 `$TOOLS` 不会按空格拆开，Trellis 报 `unknown option '--claude --cursor ...'`。用 `bash -c '...'` 运行规范 6.4 的命令，或者把参数直接写在命令里。
- 本机没有 GitHub SSH key，`gh repo clone` 走 SSH 失败。运行 `gh auth setup-git` 后用 `https://github.com/...` 克隆和推送。
- Docker 用 colima：`colima start`，第一次大约 1 到 2 分钟。

## Trellis（0.6.17）
- **顺序：先 `trellis init`，再复制 project-kit。** 如果 `AGENTS.md` 已经存在，`trellis init -y` 会直接跳过它（“Skipped: AGENTS.md (already exists)”），不会写入 `TRELLIS:START/END` 块。`.gitattributes` 已存在时会在末尾追加 `merge=union` 规则，这个没问题。
- 第一条命令必须加 `-y`，否则会交互询问是否安装 Claude Code statusLine，非交互环境下直接崩溃（`ERR_USE_AFTER_CLOSE`）。指定了工具参数时，`-y` 不会额外加 Cursor。
- **不要对同一个项目重复运行第一条 `trellis init`。** 第二次运行时没有使用 `--template`，Trellis 装了它自带的 `spec/backend/`、`spec/frontend/` 占位规范（英文“To fill”），并把 `.trellis/.template-hashes.json` 改成只跟踪 33 个文件。之后 `--append team-fastapi` 会因为 `backend/index.md` 已存在而跳过公司规范。弄乱了就删掉所有 Trellis 生成的目录，重新来一次。
- 删除范围：`.trellis .codex .cursor .opencode .kimi-code .github/{agents,copilot-instructions.md,copilot,hooks,prompts,skills} .claude/{agents,commands,hooks,settings.json,skills/trellis-*} .agents/skills/trellis-* AGENTS.md`，并恢复 `.gitattributes`。
- `--append` 也会**覆盖** `.trellis/.template-hashes.json`（只剩追加的这几个文件），并把 `.trellis/config.yaml` 中的 `registry.spec.template` 改成最后一个模板名。hash 文件用于 `trellis update` 判断文件是否被改过，追加后要把两次的 hash 合并（脚本见 template-backend-fastapi 的建设记录）。
- spec-templates 的 PR 没合并时，`main` 上没有 `marketplace/index.json`，Trellis 报 “Registry has no index.json”。用 `REG="gh:TIanle-art/spec-templates/marketplace#<分支或标签>"` 指定分支。这个地址会写进 `.trellis/config.yaml`，合并或打标签后要改成 `#v1`。
- 工具参数 `--claude --cursor --codex --copilot --opencode --kimi` 生成：`.claude/`（agents、commands、hooks、settings.json、skills/trellis-*）、`.cursor/`、`.codex/`、`.opencode/`、`.kimi-code/`、`.github/`（agents、copilot、copilot-instructions.md、hooks、prompts、skills）、`.agents/skills/trellis-*`，以及 `.trellis/`（workflow.md、scripts、agents、tasks/00-bootstrap-guidelines、workspace/<用户名>）。
- Trellis 的 skill 都以 `trellis-` 开头，和公司的 `team-*` 不冲突，`sync-skills.sh`/`check-skills.sh` 只处理 `team-*`，互不影响。
- macOS 上 Trellis 生成的 hook 用 `python3`。
- `--codex` 会提示需要在 `~/.codex/config.toml` 里开 `features.hooks = true`，这是每个开发者自己的设置。

## uv
- `uv init --app` 在 uv 0.13 默认生成 `src/` 布局、`[build-system]` 和 `[project.scripts]`，还会把 git 配置里的个人姓名和邮箱写进 `authors`。模板里删掉这些，改用 `[tool.uv] package = false`，代码直接放 `app/`。
- `fastapi[standard]` 会带上 `fastapi-cloud-cli`（以及 sentry-sdk 等）。用 `fastapi[standard-no-fastapi-cloud-cli]`。

## Docker（colima）
- 本机的 Docker CLI 没有 `docker compose` 插件，只有 Homebrew 的独立 `docker-compose`；也没有 buildx，`RUN --mount=...` 和 `# syntax=` 会报 “requires BuildKit”。Makefile 里用 `COMPOSE := $(shell docker compose version >/dev/null 2>&1 && echo 'docker compose' || echo docker-compose)` 自动选择；Dockerfile 避免 BuildKit 专有语法。
- `docker-compose up -d --wait <服务>` 会等健康检查通过再返回，Makefile 的 `db-up` 依赖它。
- 容器内 `Path(__file__).parents[4]` 会越界（`/app/app/core/config.py`），查找 `.env` 要用遍历 `parents`。
- 镜像里的健康检查没有 curl，用 `python -c "urllib.request.urlopen(...)"`。

## GitHub 推送
- 提交邮箱是私人邮箱时 push 被拒（GH007）。用 `git config user.email "<id>+<login>@users.noreply.github.com"`（id 用 `gh api user -q .id`），已提交的用 `git rebase --exec 'git commit --amend --no-edit --reset-author' <基准提交>` 改作者。只改本仓库配置。
- **`gh auth status` 的令牌范围里没有 `workflow` 时，推送任何含 `.github/workflows/` 的提交都会被拒**（“refusing to allow an OAuth App to create or update workflow ... without `workflow` scope”）。需要用户运行 `gh auth refresh -h github.com -s workflow` 并在浏览器授权。后面的模板开工前先检查 `gh auth status`。

## FastAPI / Python 写法
- 未处理异常（500）由最外层的 ServerErrorMiddleware 生成响应，晚于自己的中间件结束。`request_id` 的 ContextVar 不能在中间件的 finally 里 reset，否则 500 响应读不到 request_id（测试要断言响应体和响应头的 request_id 一致，而不只是“头存在”）。
- 用 `app.router.lifespan_context(app)` 在测试里手动运行 lifespan；`httpx.ASGITransport` 不会运行它。
- pytest-asyncio 1.x：session 级事件循环要同时设置 `asyncio_default_fixture_loop_scope` 和 `asyncio_default_test_loop_scope`，否则 asyncpg 连接池跨循环报错。
- pyright 严格模式放在 `strict = ["app", ...]`，测试用标准模式，见 ADR-002。
- Alembic：`alembic init -t async` 后，把 `sqlalchemy.url` 设为应用配置的 `database_url`；`--rev-id 0001` 让第一个迁移文件名稳定；`alembic/versions` 排除 ruff 和 pyright。
- SSE：先做限额检查（失败返回普通 JSON 错误），通过后再开始流式输出；流式开始后的失败用 `error` + `done` 事件表达。

## 模板验收的检查方法
- 建完后在 scratchpad 里 `git clone` 一份，执行 `make setup && make check`，能发现遗漏提交的文件（如 `.claude/skills/team-*`）。

## gitleaks（CI baseline）
- Trellis 的 `.trellis/.template-hashes.json` 里全是 SHA-256 哈希，会被 gitleaks 的 `generic-api-key` 规则误判，导致 `baseline` job 失败（CI 日志只写 “leaks found: 1”，看不到详情）。在项目根目录放 `.gitleaks.toml`：`[extend] useDefault = true`，再用 `[[allowlists]]` 按路径排除这一个文件。gitleaks 会自动读取仓库根目录的 `.gitleaks.toml`。
- 定位 CI 里的误报：本机 `brew install gitleaks`，运行 `gitleaks git --redact --log-opts="<base>..HEAD" -r out.json -f json`，再读 JSON。
- 建议把这个 `.gitleaks.toml` 放进 handbook 的 project-kit，所有用 Trellis 的项目都需要。

## 审查后修复的几个坑（下个模板直接避免）
- **测试不要用开发库。** conftest 里 TRUNCATE 之前先保证库名以 `_test` 结尾，自动 `CREATE DATABASE`，并用子进程执行 `alembic upgrade head`（alembic 异步 env 自己 `asyncio.run`，不能在 pytest 事件循环里调用）。`make test` 只需要 `db-up`。
- **路径参数和页码要有上界。** `int` 超出 PostgreSQL bigint 会让 asyncpg 抛 DataError，变成 500。`Path(ge=1, le=2**63-1)`、`Query(le=...)`。
- **AI 网关不接受客户端的 `system` 消息。**
- **异步生成器被关闭时抛的是 GeneratorExit，不是 CancelledError。** 用“是否正常走完”的标志判断 cancelled，不要只捕获 CancelledError。
- **OpenAI 兼容流在 HTTP 200 里也可能带 `{"error": ...}`，`usage` 字段可能是 null。**
- **compose 里不要给口令设默认值。** `env_file` 保持必需，缺少时让 compose 报错。
- **500 响应要带 CORS 头：** Starlette 默认的 `add_exception_handler(Exception, ...)` 由最外层的 ServerErrorMiddleware 生成响应，晚于 CORSMiddleware。改用放在 CORS 内层的自定义中间件捕获未处理异常并返回统一的 500（响应已开始时再抛出）。中间件添加顺序：先 Unhandled，再 CORS，最后 RequestID（后添加的在外层）。
- **`CORS_ORIGINS=*` 在配置校验里直接拒绝**，因为接口带凭据。
- **Dockerfile 不要 `FROM ghcr.io/...`：** 用 `pip install uv==x.y.z`，并声明 `ARG PIP_INDEX_URL`、`ARG UV_DEFAULT_INDEX` 方便换镜像源（未传入时不会设置环境变量）。
- **找 `.env` 只看仓库根目录：** 以含 `Makefile` 的第一个上级目录为准，不要一路向上搜；函数接受起始路径参数，方便用 `tmp_path` 测试。

## compose、Caddy 和部署（步骤 7）
- **compose 拆三层：** 基础（image，无端口）+ dev（build、本机数据库端口）+ prod（Caddy、`FORWARDED_ALLOW_IPS`）。Makefile 里 `export COMPOSE_FILE := a:b` 让所有 `docker compose` 命令自动叠加；服务器在 `.env` 里写 `COMPOSE_FILE=...`，`deploy.sh` 不用改。直接运行 `docker compose` 而不设置 `COMPOSE_FILE` 时只有基础配置。
- **`make docker-up` 必须先跑迁移**（`compose run --rm api alembic upgrade head`）。否则服务能起来、`/readyz` 是绿的，业务接口却 500（缺表）。`/readyz` 只检查连得上数据库，发现不了这个；用端到端冒烟脚本（`scripts/smoke.sh`：注册 → 登录 → AI 网关 SSE）才能发现，CI 里也跑它。
- **配置新增必填项后，本机旧的 `app.env`/`.env` 会缺项**，容器启动即报错退出——校验在正常工作，删掉旧文件让 `scripts/init-env.py` 重新生成即可。init 脚本只创建不存在的文件，不会补旧文件。
- **Caddy + SSE：** `encode` 默认会压缩 `text/*`，会缓冲 `text/event-stream`。只给 `application/json*` 配 `match`；`reverse_proxy` 加 `flush_interval -1`。语法用 `caddy validate --adapter caddyfile` 检查（`make caddy-check`，用同一个镜像版本）。
- **本机验证 Caddy：** 把站点地址改成 `localhost`，Caddy 会用内部 CA 自动签发证书，`curl -k https://localhost`。可以验证 SSE 通路和 `X-Forwarded-For`：Caddy 默认不信任客户端传来的 XFF，会改写成真实来源，所以客户端伪造的值到不了 API。
- **在中间件/脚本导入时改 `os.environ` 会污染测试进程。** 需要临时环境时用 contextmanager 保存并还原。
- 生产 compose 里 uvicorn 的 `FORWARDED_ALLOW_IPS=*` 只有在 API 端口只绑定 `127.0.0.1` 时才安全。

## 决定：TypeScript 项目的工具链（用户，2026-11-08）
跟上游走，全公司统一：**`@hey-api/openapi-ts`（从 OpenAPI 生成 SDK）、Biome（所有 TS 项目：网页、NestJS、小程序、桌面）、Vitest（单元测试）、Playwright（端到端冒烟测试）。**

这个决定还没有落到规范和模板里，需要改的地方（未动，handbook、spec-templates、ci-workflows 不在本次修改范围）：
- handbook《公司项目脚手架规范》：5.3（`packages/api-types` + `openapi-typescript` → openapi-ts 生成的 SDK）、6.7 表（ESLint + Prettier → Biome）、10.1（测试加 Vitest 之外明确 Playwright 的用法）、3.1 总表。
- spec-templates：`team-web`、`team-nestjs`、`team-miniapp`、`team-desktop` 里提到 ESLint/Prettier/Jest 的地方。
- ci-workflows `node-ci.yml`：脚本名 `lint typecheck test build` 可以不变，但 `lint` 改为 `biome check`；Playwright 需要浏览器，单独的 job。

做模板时要先验证的点（不是结论）：
- NestJS 用装饰器和 `emitDecoratorMetadata`：Biome 的装饰器解析配置、Vitest 需要 SWC 插件才能保留装饰器元数据（NestJS 默认是 Jest）。
- Taro（小程序）自带 ESLint 配置里的专用规则，换 Biome 后会丢失哪些。
- Biome 对 typescript-eslint 类型感知规则的覆盖不完整，类型错误仍由 `tsc --noEmit` 兜底（规范 6.7 已经要求）。

- 上游 `generate-client.sh` = 导出 OpenAPI → `openapi-ts` → lint；本模板的 `make openapi` 已经产出输入文件 `services/api/openapi.json`。

## 写和测可复用 workflow（阶段一）
- **用模拟的 `gh` 测 workflow 里的 shell**：用 PyYAML 把 `run:` 片段提取成文件，PATH 里放一个假的 `gh`（按环境变量返回数据、记录被调用的命令），`env -i` 清空环境后用 `bash --noprofile --norc -eo pipefail` 运行，和 GitHub 的默认一致。系统自带的 Python 没有 PyYAML，用 `uv run --with pyyaml python`。
- **macOS 和 Linux 的差异会让测试桩出错**：`seq 1 0` 在 macOS（BSD）倒着数输出两行，在 GNU 输出为空，模拟 0 个批准时用 `while [ i -lt N ]`；`wc -l` 在 macOS 会补空格，断言不要依赖数字前后的空格。
- **`printf ... | grep -q` 在 `pipefail` 下会误判**：grep 找到后提前退出，上游命令收到 SIGPIPE。实测输出较大时 30 次里失败 30 次。先存进变量，再 `grep -qxF "$x" <<< "$var"`。
- **空的 `-x` 匹配串会匹配空行**：`grep -qxF "" <<< "$labels"` 在没有标签时也成立，所以“标签名为空表示关闭豁免”要先判断 `[ -n "$WAIVER_LABEL" ]`。
- **actionlint**：`brew install actionlint shellcheck`，本机版本和 `self-check.yml` 用的 docker 镜像版本不同时两个都跑一遍；它不展开其他仓库的 `uses:`，所以要用临时分支实际试跑。
- **试跑可复用 workflow 的改动**：在使用方仓库建临时分支，`uses: ...@<分支名>`，并临时把分支加到 `on.push.branches`（否则不开 PR 就不会触发），跑完删除分支。
- **可复用 workflow 里的 `make` 目标**：参数通过 `env:` 传入再 `for t in $TARGETS`，不要把 `${{ inputs.* }}` 直接拼进脚本；日志输出步骤用 `|| true`，不要掩盖前面真正的失败。
- **改默认值算不算不兼容**：ci-workflows 自己的版本规则写“改变默认行为打 v2”。v1.1 改了 Python 和 PostgreSQL 的默认值，因为当时没有项目使用 v1 才放在 v1 上，README 里写了这个例外。

## 改规范文档（阶段二）
- **改长文档用脚本做精确替换**：每处 `rep(old, new)` 断言只匹配一次，改错位置会立刻报错；按小节标题用 `s.index` 切片替换整段（13.3、5.3、6.7）。
- **文档里的相对链接和目录锚点要有检查器**：GitHub 的锚点规则是小写、去掉标点（保留字母数字、下划线、连字符，中文保留）、空格变连字符、重复加 `-1`。写好后先用故意写错的链接验证它会报错，再跑基线，再跑改动后的结果。脚本在 scratchpad 的 `linkcheck.py`，需要时放进 handbook 的 CI。
